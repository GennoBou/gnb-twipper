# アーキテクチャ設計書 (Architecture Design)

本ドキュメントでは、`gnb-twipper` のシステム構造、主要コンポーネント間の連携、データ取得モデルについて解説します。

---

## 1. 全体構造図 (Manifest V3)

```text
+-----------------------------------------------------------------------+
|                            Google Chrome                              |
|                                                                       |
|  [ Content Script (Twitch タブ) ]                                      |
|  +-----------------------------------+   chrome.runtime.sendMessage  |
|  | - MutationObserver (DOM監視)      | <----------------------------+ |
|  | - GnbNavTrigger.svelte (注入UI)   |                              | |
|  | - DOM Scrape Fallback             | ---------------------------->+ |
|  | - Sub-only Overlay Detector       |                              | |
|  +-----------------------------------+                              | |
|                                                                     | |
|  [ Service Worker (Background) ]                                    | |
|  +---------------------------------------------------------------+  | |
|  | - Rotation Engine (rotation.ts): キュー管理・タイマー管理      |  | |
|  | - GQL API Client: Twitch GraphQL 経由でライブ一覧を高速取得   |  | |
|  | - Storage Manager: chrome.storage.local との同期             |  | |
|  | - Navigation Controller: chrome.tabs.update による画面遷移   |  | |
|  +---------------------------------------------------------------+  | |
|         ^                                                           | |
|         | chrome.runtime.sendMessage                                | |
|  [ Extension Popup / Options Page ]                                 | |

|  +-----------------------------------+                              | |
+-----------------------------------------------------------------------+
```

---

## 2. コア設計思想

1. **セキュア & ノン・インベシブ**:
   - 独自の認証トークン管理やパスワード入力を排除し、ユーザーが普段使用しているブラウザの既存セッション（Cookie）をそのまま活用します。
   - Twitch のセキュリティ（Twitch Integrity / Bot検知）を侵害せず、通常のユーザーブラウジングと同一の振る舞いを維持します。
2. **ハイブリッドデータ取得 (GQL API + DOM Scrape)**:
   - 信頼性と即応性の両立のため、API 直接取得と DOM 画面解析の二重化を採用しています。

---

## 3. ハイブリッドデータ取得モデル

### プライマリ: Twitch GQL API
- **実行場所**: Service Worker (`background.ts`)
- **仕組み**: Twitch Web が内部で使用している GraphQL エンドポイントへクエリを送信し、フォロー中のライブ配信者一覧、カテゴリー、視聴者数、サブスク限定フラグを一括取得します。
- **メリット**: バックグラウンドで高速かつ確実にリストを取得でき、ページ DOM の描画遅延に影響されません。

### セカンダリ: DOM スクラップ フォールバック
- **実行場所**: Content Script (`content.ts`)
- **トリガー**: GQL API がレート制限、CORS、未認証等で失敗した場合。
- **仕組み**: Twitch の左サイドバーナビゲーション (`nav[aria-label]`) に描画されているフォロー中ライブチャンネル要素を探索し、チャンネル名とライブ状態を抽出して Service Worker へ送信します。

## 4. ローテーション状態遷移 (State Machine)

`rotation.ts` では以下のステータスを管理します：

```text
                  +---------------+
                  |  STOP (停止)  |
                  +---------------+
                          |
             AUTO 開始     |  AUTO 停止
                          v
                  +---------------+
   +------------> | ROTATING (巡回) | <-----------+
   |              +---------------+              |
   |                      |                      |
   | 2人以上ライブ再開     | 配信者が1人 / 0人    | タイマー完了 / SKIP
   |                      v                      |
   |              +---------------+              |
   +------------- | STANDBY (待機) |              |
                  +---------------+              |
                          |                      |
                          +----------------------+
```

- **目標視聴時間 (Target Watch Time)**:
  - Twitch の連続視聴（Watch Streak）やチャンネルポイント獲得要件を満たすため、各配信者ごとに「最低限視聴する目標時間」（初期値6分）を管理します。
  - 目標視聴時間に達していない配信者が優先して巡回キューの先頭に配置されます。
- **待機モード**:
  - `standbySingle`: ライブ中のフォロー中配信者が1人のみの場合、無駄なリロードを停止して視聴を継続。
  - `standbyNone`: ライブ配信者が0人の場合は待機し、定期ポーリングでライブ開始を検知すると巡回を再開。

---

## 5. サブスク限定配信の検出ロジック

1. **GQL メタデータ判定**: GQL API から取得したストリーム情報の属性をチェック。
2. **DOM オーバーレイ検知**: Content Script の `MutationObserver` がプレイヤー上に表示される「サブスクライバー限定」のメッセージ要素を監視。
3. **無料プレビュー連動**:
   - 無料プレビューが提供されている場合、プレビュータイマーが終了して本編がロックされたイベントを検知した時点で次チャンネルへスキップ。

---

## 6. Svelte 5 + Web Component 統合

- Content Script でマウントされる `GnbNavTrigger.svelte` は、Twitch のヘッダー検索バー横に DOM 注入されます。
- Twitch 側のスタイル崩れを防ぐため、Scoped CSS および Tailwind CSS のユーティリティクラスを限定的に適用しています。
- Svelte 5 の **Runes** (`$state`, `$derived`, `$effect`) を全面的に採用し、拡張機能の `chrome.storage.onChanged` イベントと同期して UI をリアルタイムにリアクティブ更新します。
